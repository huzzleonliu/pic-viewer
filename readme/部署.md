# 部署

根目录 [README](../README.md) 是快速上手。本文列出实际生效的环境变量、端口、镜像和挂载约定。

## 进程角色

生产 Compose 与开发 Compose 都是两个容器：

| 服务 | 职责 |
| --- | --- |
| `pic-viewer` | Leptos/Axum 应用。浏览器只连它。 |
| `imgproxy` | 按 `local://` 路径读同一棵相册树，生成缩略图 / 预览。不对外暴露（开发栈例外，见下）。 |

应用用 `IMGPROXY_URL` 在服务端拉取 imgproxy，再把结果转给浏览器。浏览器从不直连 imgproxy。未设置或为空时，`/thumb` 与 `/preview` 退回原图（与 `/media` 相同数据，预览仍支持 Range）。

`PIC_ROOT`（应用）和 `IMGPROXY_LOCAL_FILESYSTEM_ROOT`（imgproxy）必须指向**同一棵目录树**。Compose 里两者都挂 `${PIC_DIR}:/data`。

## 端口

| 场景 | 主机 | 容器内 | 说明 |
| --- | --- | --- | --- |
| 生产 Compose 应用 | `PIC_HOST_PORT`（默认 `3020`） | `3000` | `LEPTOS_SITE_ADDR=0.0.0.0:3000` |
| 生产 Compose imgproxy | 不映射 | `8080` | 仅 compose 内部 DNS `imgproxy:8080` |
| 开发 Compose 应用 | `PIC_HOST_PORT`（默认 `3020`） | `3020` | `cargo leptos watch`，与 `Cargo.toml` metadata 一致 |
| 开发 Compose 热更新 | `LEPTOS_RELOAD_PORT`（默认 `3021`） | 同左 | 与容器环境变量一致 |
| 开发 Compose imgproxy | `IMGPROXY_HOST_PORT`（默认 `8080`） | `8080` | 方便本机 `cargo leptos watch` 直连 |
| 生产 Dockerfile 默认 | — | `3000` | 镜像 `EXPOSE 3000` |
| Kubernetes Service | `80` | `3000`（name: `http`） | 见 `k8s/deployment.yaml` |

健康检查：`GET /health` → `ok`。K8s 清单里 readiness / liveness 都打这条。

## 环境变量（应用）

| 变量 | 作用 | 默认 / Compose 取值 |
| --- | --- | --- |
| `PIC_ROOT` | 托管根目录。不存在则启动时创建。相对路径相对进程 cwd。 | 代码默认 `./pics`；Compose 均为 `/data` |
| `IMGPROXY_URL` | imgproxy 根 URL，无尾斜杠亦可。空则缩略图 / 预览用原图。 | 生产 / 开发 Compose：`http://imgproxy:8080` |
| `LEPTOS_SITE_ADDR` | 监听 `host:port` | 生产镜像 / 生产 Compose：`0.0.0.0:3000`；watch：`0.0.0.0:3020` |
| `LEPTOS_SITE_ROOT` | 静态站点根（wasm / css） | 生产：`/app/site`；本机 watch：`target/site` |
| `LEPTOS_OUTPUT_NAME` | 前端包名，对应 `/pkg/{name}.js` 等 | `pic-viewer` |
| `LEPTOS_SITE_PKG_DIR` | 包目录名 | `pkg` |
| `LEPTOS_RELOAD_PORT` | 仅开发 watch 热更新 | 开发 Compose：`3021` |

`Cargo.toml` 的 `[package.metadata.leptos]` 在 `cargo leptos watch` / `build` 时生效：`site-addr = 0.0.0.0:3020`，`reload-port = 3021`，`style-file = style/main.css`，`assets-dir = public`。生产容器不跑 cargo-leptos，靠上面的 `LEPTOS_*` 环境变量。

## `.env`（Compose 推荐用法）

模板是仓库根目录的 [`example.env`](../example.env)。Compose 会自动读取**项目根目录**的 `.env`，用来替换 yaml 里的 `${变量}`。

```bash
cp example.env .env
# 编辑 PIC_DIR、PIC_VIEWER_IMAGE、PIC_HOST_PORT 等
podman compose up -d
```

`.env` 已在 `.gitignore` 中，不要提交真实相册路径。改完已运行的栈后需要再 `podman compose up -d` 才会用上新值。

| 变量 | 谁读 | 作用 | 模板缺省 |
| --- | --- | --- | --- |
| `PIC_DIR` | 生产 / 开发 compose 插值 | 宿主机相册，挂到容器 `/data` | `./test/pic` |
| `PIC_VIEWER_IMAGE` | 仅生产 compose | 应用镜像 | `ghcr.io/huzzleonliu/pic-viewer:latest` |
| `PIC_HOST_PORT` | 两份 compose | 浏览器访问的主机端口 | `3020` |
| `LEPTOS_RELOAD_PORT` | 开发 compose | 热更新端口（主机与容器一致） | `3021` |
| `IMGPROXY_HOST_PORT` | 开发 compose | 把 imgproxy 映到主机，供本机 watch | `8080` |
| `PIC_ROOT` | **仅**本机 `cargo leptos watch` | 进程看到的托管根；compose 应用容器固定 `/data` | 模板里默认注释掉 |
| `IMGPROXY_URL` | **仅**本机 watch | 例如 `http://127.0.0.1:8080` | 模板里默认注释掉 |

容器内应用的 `PIC_ROOT`、`IMGPROXY_URL`、`LEPTOS_SITE_*` 仍写在 compose 的 `environment:` 里，不要把宿主机路径写进容器的 `PIC_ROOT`。

没有 `.env` 时，yaml 中 `${VAR:-缺省}` 仍然可用。命令行 `PIC_DIR=/photos podman compose up -d` 会覆盖 `.env`（一般不必再用）。

## imgproxy 参数（Compose 已写死）

两边 compose 的 imgproxy 服务使用镜像 `docker.io/darthsim/imgproxy:v3.27.2`，环境变量：

| 变量 | 值 | 含义 |
| --- | --- | --- |
| `IMGPROXY_LOCAL_FILESYSTEM_ROOT` | `/data` | `local://` 源文件根，须与应用 `PIC_ROOT` 同一棵树 |
| `IMGPROXY_BIND` | `0.0.0.0:8080` | 监听 |
| `IMGPROXY_TTL` | `31536000` | 缓存秒数（约一年） |
| `IMGPROXY_USE_ETAG` | `true` | 转发 ETag |
| `IMGPROXY_MAX_SRC_RESOLUTION` | `50` | 源图像素上限（百万像素量级，imgproxy 自己的单位） |
| `IMGPROXY_MAX_SRC_FILE_SIZE` | `104857600` | 源文件最大 100 MiB |

Compose 还设置 `user: "1000:1000"`、`userns_mode: keep-id`，相册卷对 imgproxy 为 **只读**（`:ro,Z`），对应用为读写（`:Z`）。生产 imgproxy 仅 `expose: 8080`，不映射到主机。

应用向 imgproxy 发的处理串（写死在 `src/function/fs/media.rs`）：

| 路由 | 处理 | 效果 |
| --- | --- | --- |
| `/thumb/...` | `rs:fill:184:128:0/g:ce/q:70/f:webp` | 184×128 裁切，WebP 质量 70 |
| `/preview/...` | `rs:fit:1920:1920:0/q:80/f:webp` | 最长边 ≤ 1920，WebP 质量 80 |

URL 形态：`{IMGPROXY_URL}/insecure/{processing}/{urlsafe-base64(local:///{相对路径})}`。无签名（`insecure`）。并发上限 16（信号量）。上游 HTTP 超时 30 秒，不跟随重定向。

未配置 imgproxy 或请求失败时：无 base 则直接按原图流；请求出错返回 502；路径非法或不是文件返回 404。

## HTTP 路由（对外）

浏览器只应访问应用：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/health` | 健康检查，正文 `ok` |
| `GET` | `/media/{*path}` | 原图，支持 `Range`，206 分块 |
| `GET` | `/thumb/{*path}` | 缩略图（imgproxy 或原图回退） |
| `GET` | `/preview/{*path}` | 预览图 |
| `GET` | `/export/{id}` | 导出下载（临时 id，约 15 分钟清理） |
| `GET` | `/` 及 `/pkg/...` | 页面与 wasm/css；其余为 Leptos server function（`/api/...`） |

`path` 为相对 `PIC_ROOT` 的路径，经 `resolve_path` 校验。点文件不会出现在列表里，但直接猜 URL 仍受沙箱约束。

## 生产 Compose

文件：[`docker-compose.yml`](../docker-compose.yml)，项目名 `pic-viewer`。

```bash
cp example.env .env
# 编辑 .env
podman compose up -d
# 浏览器 http://127.0.0.1:$PIC_HOST_PORT
podman compose down
```

应用镜像内进程用户 uid 1000，数据卷 `/data`。`restart: unless-stopped`。

## 开发 Compose

文件：[`dev.docker-compose.yml`](../dev.docker-compose.yml)，项目名 `pic-viewer-dev`。与生产栈抢 `PIC_HOST_PORT`，先 `podman compose down`。同样读根目录 `.env`。

```bash
cp example.env .env
podman compose down
podman compose -f dev.docker-compose.yml up --build
```

| 项 | 值 |
| --- | --- |
| 构建 | `Dockerfile.dev`，镜像名 `localhost/pic-viewer-dev:local` |
| 命令 | `cargo leptos watch` |
| 源码 | `.:/app:Z` |
| Cargo 缓存 | `./.dev-cache/cargo` → `/cache/cargo` |
| target | `./.dev-cache/target` → `/app/target` |
| `CARGO_HOME` | `/cache/cargo`（避免覆盖镜像里装好的 `cargo-leptos`） |
| `restart` | `no` |

第一次 `up --build` 会编工具链镜像并完整编译，之后增量快很多。看日志：`podman compose -f dev.docker-compose.yml logs -f pic-viewer`。

## 本机构建（不经过 Compose 应用容器）

需要 Rust stable、`wasm32-unknown-unknown`（见 `rust-toolchain.toml`）和 `cargo-leptos`。

```bash
rustup target add wasm32-unknown-unknown
cargo install cargo-leptos --locked
cp example.env .env
# 取消注释 PIC_ROOT、IMGPROXY_URL，并与 PIC_DIR / IMGPROXY_HOST_PORT 对齐
podman compose -f dev.docker-compose.yml up imgproxy
set -a && source .env && set +a
cargo leptos watch                            # 开发
cargo leptos build --release                  # 产物：target/release/pic-viewer 与 target/site
```

发布镜像：

```bash
podman build -t localhost/pic-viewer:local .
# 在 .env 中设置 PIC_VIEWER_IMAGE=localhost/pic-viewer:local
podman compose up -d
```

生产 `Dockerfile`：builder 阶段 `cargo leptos build --release`；运行阶段 `debian:bookworm-slim`，用户 `app` uid 1000，二进制 `/app/pic-viewer`，静态文件 `/app/site`，默认 `PIC_ROOT=/data`，`EXPOSE 3000`。

测试：

```bash
cargo test --lib --features ssr
cargo check --features ssr --bins --lib
cargo check --lib --features hydrate --target wasm32-unknown-unknown
```

## Kubernetes

清单：[`k8s/deployment.yaml`](../k8s/deployment.yaml)。

当前示例**只有应用容器**，没有 imgproxy sidecar，也没有 `IMGPROXY_URL`。部署后缩略图 / 预览走原图。把镜像推到仓库后改 `image:`（现为 `pic-viewer:latest`，`imagePullPolicy: IfNotPresent`）。

已写明的应用参数：

- `PIC_ROOT=/data`
- `LEPTOS_SITE_ROOT=/app/site`
- `LEPTOS_SITE_ADDR=0.0.0.0:3000`
- `LEPTOS_OUTPUT_NAME=pic-viewer`
- `LEPTOS_SITE_PKG_DIR=pkg`
- 端口 `3000` / name `http`
- PVC `pic-viewer-data`，默认 20 Gi，`ReadWriteOnce`，挂到 `/data`
- 探针：`GET /health`
- 运行用户 1000，`fsGroup: 1000`

改成节点目录时，把 volume 换成注释里的 `hostPath`。

若要与 Compose 一样用边车，在同一 Pod 增加 imgproxy 容器（`IMGPROXY_LOCAL_FILESYSTEM_ROOT=/data`，共享 data volume），并给应用设置 `IMGPROXY_URL=http://127.0.0.1:8080`（同 Pod localhost）或对应 sidecar 端口。不要把 imgproxy 单独做成对公网的 Service。

## 权限与安全要点

- 所有文件 API 经 `resolve_path`：禁止 `\0`、`..` 等组件，canonicalize 后必须仍在 `PIC_ROOT` 下。
- 不能删除或重命名根目录本身。
- 列表跳过名称以 `.` 开头的项。
- 递归扫图不跟随符号链接（`read_dir` + `file_type` 的目录判断）。
- imgproxy 使用 `insecure` 本地源，依赖网络隔离：生产不要把 8080 映射到公网。
